# W-N06 · Servidor web (Apache + PHP + HTTPS)

Documentación de la configuración del servidor web de la DMZ. Muestra el contenido de la tabla `equipaments` de la base de datos B-N06 a través de una página PHP servida por HTTPS.

## 1. Resumen

| Dato | Valor |
|---|---|
| Hostname | `W-N06` |
| Sistema operativo | Ubuntu Server 22.04 LTS |
| Red | DMZ `10.6.1.0/24` |
| IP | `10.6.1.10/24` (interfaz `enp3s0`) |
| Gateway / DNS | `10.6.1.1` (R-N06) |
| Servicios | Apache 2.4.52, PHP 8.1, SSH |
| Puertos abiertos | 22/tcp (SSH), 80/tcp (HTTP → redirige), 443/tcp (HTTPS) |
| Base de datos | `10.6.2.10` (B-N06), usuario `webuser` solo con `SELECT` |

La interfaz `enp1s0` va por DHCP y es la red de gestión de Isard (acceso por SSH e Internet). La interfaz `enp3s0` es la de la DMZ.

## 3. Configuración de red

Se edita el netplan que generó el instalador:

```bash
sudo nano /etc/netplan/00-installer-config.yaml
```

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: true
    enp3s0:
      dhcp4: false
      addresses:
        - 10.6.1.10/24
      routes:
        - to: 10.6.2.0/24
          via: 10.6.1.1
      nameservers:
        addresses:
          - 10.6.1.1
```

La ruta `10.6.2.0/24 via 10.6.1.1` permite llegar a la Intranet (B-N06) a través del router. No se define `default` en `enp3s0` porque la salida a Internet va por `enp1s0`.

Aplicar con `netplan try` (revierte solo si algo falla):

```bash
sudo chmod 600 /etc/netplan/*.yaml
sudo netplan try
```

Comprobación:

```bash
ip -br a
ip route
```

Resultado esperado: `enp3s0` con `10.6.1.10/24` y la ruta `10.6.2.0/24 via 10.6.1.1 dev enp3s0`.

## 6. Sitio web (HTTP)

### 6.1 Directorio del sitio

```bash
sudo mkdir -p /var/www/w-n06/public
sudo chown -R www-data:www-data /var/www/w-n06
```

Solo `public/` es accesible desde el navegador. Las credenciales de la base de datos se guardan fuera del DocumentRoot (ver punto 7).

### 6.2 Virtual host

```bash
sudo nano /etc/apache2/sites-available/w-n06.conf
```

```apache
<VirtualHost *:80>
    ServerName W-N06
    DocumentRoot /var/www/w-n06/public

    <Directory /var/www/w-n06/public>
        Options -Indexes
        AllowOverride None
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/w-n06_error.log
    CustomLog ${APACHE_LOG_DIR}/w-n06_access.log combined
</VirtualHost>
```

`Options -Indexes` impide listar el contenido de las carpetas. Además se desactiva el módulo `autoindex`:

```bash
sudo a2dismod -f autoindex
sudo systemctl reload apache2
```

## 7. Conexión a la base de datos

### 7.1 Credenciales fuera del DocumentRoot

```bash
sudo mkdir -p /etc/w-n06
sudo nano /etc/w-n06/db.php
```

```php
<?php
return [
    'host' => '10.6.2.10',
    'name' => 'equipaments_db',
    'user' => 'webuser',
    'pass' => '<PASSWORD_WEBUSER>',
];
```

Permisos: solo root y el grupo de Apache pueden leerlo.

```bash
sudo chown root:www-data /etc/w-n06/db.php
sudo chmod 640 /etc/w-n06/db.php
```

### 7.2 Archivos de la página

La página se compone de tres archivos. `db.php` (punto 7.1) va fuera del DocumentRoot; `index.php` y `style.css` van en `public/`.

| Archivo | Ruta en el servidor | Función |
|---|---|---|
| `db.php` | `/etc/w-n06/db.php` | Credenciales de la base de datos |
| `index.php` | `/var/www/w-n06/public/index.php` | Lógica y HTML de la página |
| `style.css` | `/var/www/w-n06/public/style.css` | Diseño visual (estilo "plano técnico") |

```bash
sudo nano /var/www/w-n06/public/index.php
sudo nano /var/www/w-n06/public/style.css
sudo chown www-data:www-data /var/www/w-n06/public/index.php /var/www/w-n06/public/style.css
sudo chmod 644 /var/www/w-n06/public/index.php /var/www/w-n06/public/style.css
```

#### `index.php`

Lista las tablas de la base de datos y muestra la seleccionada con paginación de 25 filas. Puntos de seguridad aplicados:

- Conexión con **PDO** y errores por excepción; el detalle del error va al log, no al navegador.
- El nombre de la tabla se valida contra `SHOW TABLES` (evita inyección SQL por el parámetro `t`).
- Todo el contenido se pasa por `htmlspecialchars` (evita XSS).
- Timeout de 5 s en la conexión.

El diseño no está en el PHP: se carga con `<link rel="stylesheet" href="style.css">`.

<details>
<summary>Ver código completo de <code>index.php</code></summary>

```php
<?php
$cfg = require '/etc/w-n06/db.php';

try {
    $pdo = new PDO(
        "mysql:host={$cfg['host']};dbname={$cfg['name']};charset=utf8mb4",
        $cfg['user'],
        $cfg['pass'],
        [
            PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_TIMEOUT => 5,
        ]
    );
} catch (PDOException $e) {
    http_response_code(500);
    error_log($e->getMessage());
    exit('No se pudo conectar con la base de datos.');
}

$tables = $pdo->query('SHOW TABLES')->fetchAll(PDO::FETCH_COLUMN);
$table  = $_GET['t'] ?? ($tables[0] ?? '');
if (!in_array($table, $tables, true)) {
    http_response_code(400);
    exit('Tabla no válida.');
}

$perPage = 25;
$page    = max(1, (int)($_GET['p'] ?? 1));
$offset  = ($page - 1) * $perPage;

$total = (int)$pdo->query("SELECT COUNT(*) FROM `$table`")->fetchColumn();
$rows  = $pdo->query("SELECT * FROM `$table` LIMIT $perPage OFFSET $offset")
             ->fetchAll(PDO::FETCH_ASSOC);
$pages = max(1, (int)ceil($total / $perPage));

function h($s) { return htmlspecialchars((string)$s, ENT_QUOTES, 'UTF-8'); }
?>
<!DOCTYPE html>
<html lang="ca">
<head>
<meta charset="utf-8">
<title>W-N06 · <?= h($table) ?></title>
<link rel="stylesheet" href="style.css">
</head>
<body>
<h1>Servidor W-N06</h1>
<p>Taules:
<?php foreach ($tables as $t): ?>
  <a href="?t=<?= urlencode($t) ?>"><?= h($t) ?></a>
<?php endforeach; ?>
</p>
<h2><?= h($table) ?> (<?= $total ?> files)</h2>
<div class="scroll">
<table>
<?php if ($rows): ?>
  <tr><?php foreach (array_keys($rows[0]) as $c): ?><th><?= h($c) ?></th><?php endforeach; ?></tr>
  <?php foreach ($rows as $r): ?>
    <tr><?php foreach ($r as $v): ?><td><?= h($v) ?></td><?php endforeach; ?></tr>
  <?php endforeach; ?>
<?php else: ?>
  <tr><td>Sense dades</td></tr>
<?php endif; ?>
</table>
</div>
<p>
<?php if ($page > 1): ?><a href="?t=<?= urlencode($table) ?>&p=<?= $page - 1 ?>">« Anterior</a><?php endif; ?>
Pàgina <?= $page ?> de <?= $pages ?>
<?php if ($page < $pages): ?><a href="?t=<?= urlencode($table) ?>&p=<?= $page + 1 ?>">Següent »</a><?php endif; ?>
</p>
</body>
</html>
```

</details>

#### `style.css`

Estilo visual tipo plano técnico (cianotipia): fondo con cuadrícula, cabecera de tabla fija, resaltado de fila y columna al pasar el ratón, paginación en un cajetín y animaciones suaves. Solo usa CSS: no modifica la lógica del PHP.

Detalles a tener en cuenta:

- Las fuentes (*Barlow Condensed* e *IBM Plex Sans*) se piden a Google Fonts con `@import`. Si el cliente no tiene Internet, se usan las fuentes de reserva definidas en `--display` y `--text`, y la página sigue funcionando.
- El grano de papel es un SVG incrustado en el propio CSS, sin peticiones externas.
- Con `prefers-reduced-motion` el sistema desactiva las animaciones (accesibilidad).
- El resaltado de columna cubre hasta 20 columnas (la tabla `equipaments` tiene más, por lo que en las columnas posteriores solo se resalta la fila).

## 8. Firewall (UFW)

```bash
sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp comment 'SSH'
sudo ufw allow 80/tcp comment 'HTTP (redirige a HTTPS)'
sudo ufw allow 443/tcp comment 'HTTPS'
sudo ufw show added
sudo ufw enable
sudo ufw status verbose
```

```text
Status: active
Default: deny (incoming), allow (outgoing), disabled (routed)

To                         Action      From
22/tcp                     ALLOW IN    Anywhere        # SSH
80/tcp                     ALLOW IN    Anywhere        # HTTP (redirige a HTTPS)
443/tcp                    ALLOW IN    Anywhere        # HTTPS
```

> El firewall de W-N06 (UFW) y el del router (iptables en R-N06) son independientes. Que el tráfico pase en uno no implica que pase en el otro.

## 9. HTTPS con certificado autofirmado

### 9.1 Generar certificado y clave

El certificado incluye `subjectAltName` con el nombre y la IP del servidor.

```bash
sudo mkdir -p /etc/ssl/w-n06
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/w-n06/w-n06.key \
  -out /etc/ssl/w-n06/w-n06.crt \
  -subj "/C=ES/ST=Barcelona/O=ASIX/CN=W-N06" \
  -addext "subjectAltName=DNS:W-N06,IP:10.6.1.10"
sudo chmod 600 /etc/ssl/w-n06/w-n06.key
```

### 9.2 Activar módulos

```bash
sudo a2enmod ssl headers rewrite
```

### 9.3 Virtual host HTTPS

```bash
sudo nano /etc/apache2/sites-available/w-n06-ssl.conf
```

```apache
<VirtualHost *:443>
    ServerName W-N06
    DocumentRoot /var/www/w-n06/public

    SSLEngine on
    SSLCertificateFile    /etc/ssl/w-n06/w-n06.crt
    SSLCertificateKeyFile /etc/ssl/w-n06/w-n06.key

    Header always set Strict-Transport-Security "max-age=31536000"

    <Directory /var/www/w-n06/public>
        Options -Indexes
        AllowOverride None
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/w-n06_ssl_error.log
    CustomLog ${APACHE_LOG_DIR}/w-n06_ssl_access.log combined
</VirtualHost>
```

### 9.4 Redirección de HTTP a HTTPS

Se añade al virtual host del puerto 80 (`w-n06.conf`):

```apache
    RewriteEngine On
    RewriteRule ^/?(.*)$ https://%{HTTP_HOST}/$1 [R=301,L]
```

Quedando el archivo así:

```apache
<VirtualHost *:80>
    ServerName W-N06
    DocumentRoot /var/www/w-n06/public

    RewriteEngine On
    RewriteRule ^/?(.*)$ https://%{HTTP_HOST}/$1 [R=301,L]

    <Directory /var/www/w-n06/public>
        Options -Indexes
        AllowOverride None
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/w-n06_error.log
    CustomLog ${APACHE_LOG_DIR}/w-n06_access.log combined
</VirtualHost>
```

### 9.5 Activar y comprobar

```bash
sudo a2ensite w-n06-ssl.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
sudo apache2ctl -S
ss -tlnp | grep -E ':80|:443'
```

`apache2ctl -S` debe mostrar los dos virtual hosts (`*:443` y `*:80`) y `ss` los puertos 80 y 443 en escucha.

## 10. Endurecimiento de Apache y PHP

### 10.1 Ocultar versión y desactivar TRACE

```bash
sudo nano /etc/apache2/conf-available/security.conf
```

```apache
ServerTokens Prod
ServerSignature Off
TraceEnable Off
```

```bash
sudo a2enconf security
echo "ServerName W-N06" | sudo tee /etc/apache2/conf-available/servername.conf
sudo a2enconf servername
```

La directiva `ServerName` global elimina el aviso `AH00558` al arrancar Apache.

### 10.2 Cabeceras de seguridad

En `/etc/apache2/sites-available/w-n06-ssl.conf`, dentro del `VirtualHost *:443`, bajo la cabecera HSTS:

```apache
    Header always set X-Content-Type-Options "nosniff"
    Header always set X-Frame-Options "SAMEORIGIN"
    Header always set Referrer-Policy "no-referrer"
```

### 10.3 PHP

```bash
sudo nano /etc/php/8.1/apache2/php.ini
```

```ini
expose_php = Off
display_errors = Off
log_errors = On
```

`display_errors = Off` evita que un fallo de PHP muestre en el navegador rutas, usuarios de la base de datos o la IP de B-N06. Los errores quedan en `/var/log/apache2/w-n06_ssl_error.log`.

### 10.4 Aplicar

```bash
sudo apache2ctl configtest
sudo systemctl restart apache2
```

Se usa `restart` (no `reload`) para que PHP relea `php.ini`.

## 12. Problemas encontrados

| Síntoma | Causa | Solución |
|---|---|---|
| `usermod: cannot lock /etc/passwd` | Se ejecutó `usermod` sin `sudo` | Repetir con `sudo` |
| `AH00558: Could not reliably determine the server's fully qualified domain name` | Falta `ServerName` global | Crear `servername.conf` y `a2enconf servername` |
| `curl -kI https://localhost` devolvió `500` justo tras el cambio de `php.ini` | Apache aún no tenía la configuración aplicada de forma consistente | `apache2ctl configtest` y `systemctl restart apache2`; tras ello devolvió `200 OK` |
| `php -i` muestra `expose_php => On` | Es el `php.ini` de la CLI, no el de Apache | Comprobar las cabeceras HTTP con `curl -kI` |
