# B-N06 · Servidor de base de datos (MySQL)

Documentación de la configuración del servidor de base de datos de la Intranet. Almacena el dataset de equipamientos del Ajuntament de Barcelona, que consulta el servidor web W-N06.

## 1. Resumen

| Dato | Valor |
|---|---|
| Hostname | `B-N06` |
| Sistema operativo | Ubuntu Server 24.04 LTS |
| Red | Intranet `10.6.2.0/24` |
| IP | `10.6.2.10/24` (interfaz `enp3s0`) |
| Gateway / DNS | `10.6.2.1` (R-N06) |
| Servicios | MySQL 8.0, SSH |
| Puertos abiertos | 22/tcp (SSH), 3306/tcp solo desde `10.6.1.10` (W-N06) |
| Base de datos | `equipaments_db`, tabla `equipaments` (2709 filas) |

La interfaz `enp1s0` va por DHCP y es la red de gestión de Isard (Internet y acceso por SSH). La interfaz `enp3s0` es la de la Intranet.

> El nombre de la interfaz puede variar según la VM. Comprobarlo siempre con `ip -br a` antes de editar el netplan.

## 3. Configuración de red

```bash
sudo nano /etc/netplan/50-cloud-init.yaml
```

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: true
    enp3s0:
      dhcp4: false
      addresses:
        - 10.6.2.10/24
      routes:
        - to: 10.6.1.0/24
          via: 10.6.2.1
      nameservers:
        addresses:
          - 10.6.2.1
```

La ruta `10.6.1.0/24 via 10.6.2.1` permite responder a W-N06 (DMZ) a través del router.

```bash
sudo chmod 600 /etc/netplan/*.yaml
sudo netplan try
ip route
```

Resultado esperado:

```text
default via 192.168.120.1 dev enp1s0 proto dhcp ...
10.6.1.0/24 via 10.6.2.1 dev enp3s0 proto static
10.6.2.0/24 dev enp3s0 proto kernel scope link src 10.6.2.10
```

## 5. Instalación de MySQL

```bash
sudo apt install -y mysql-server
sudo systemctl enable --now mysql
```

Versión instalada: MySQL 8.0.

### 5.1 Escuchar en la IP de la Intranet

Por defecto MySQL solo escucha en `localhost`. Se cambia `bind-address`:

```bash
sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf
```

```ini
bind-address = 10.6.2.10
mysqlx-bind-address = 127.0.0.1
```

```bash
sudo systemctl restart mysql
ss -tlnp | grep 3306
```

```text
LISTEN 0 151 10.6.2.10:3306   0.0.0.0:*
LISTEN 0 70  127.0.0.1:33060  0.0.0.0:*
```

El puerto 3306 queda en la IP `10.6.2.10`; el 33060 (X Protocol) solo en local.

## 6. Descarga y preparación del CSV

### 6.1 Descargar

```bash
wget -O /tmp/equipaments.csv "https://opendata-ajuntament.barcelona.cat/data/dataset/f36b60f2-9541-4d08-b0f9-b0a9313fab3d/resource/29d9ff10-6892-4f16-9012-d5c4997857e7/download"
```

### 6.2 Inspeccionar

```bash
head -3 /tmp/equipaments.csv
file /tmp/equipaments.csv
wc -l /tmp/equipaments.csv
```

```text
/tmp/equipaments.csv: CSV Unicode text, UTF-16, little-endian text
2710 /tmp/equipaments.csv
```

Datos relevantes:

- Separador: **coma**, con campos entre comillas.
- Codificación: **UTF-16 LE**, que MySQL no puede cargar con `CHARACTER SET utf8mb4`.
- 2710 líneas: 1 de cabecera y **2709 registros**.

### 6.3 Convertir a UTF-8

```bash
iconv -f UTF-16 -t UTF-8 /tmp/equipaments.csv -o /tmp/equipaments_utf8.csv
sed -i '1s/^\xEF\xBB\xBF//' /tmp/equipaments_utf8.csv   # quita BOM si lo hay
sed -i 's/\r$//' /tmp/equipaments_utf8.csv              # CRLF -> LF
file /tmp/equipaments_utf8.csv
```

## 7. Base de datos, tabla y usuarios

### 7.1 Generar el `CREATE TABLE` desde la cabecera

El CSV tiene unas 40 columnas. En lugar de escribirlas a mano, un script genera el SQL a partir de la cabecera, con todas las columnas como `TEXT`:

```bash
python3 - <<'EOF'
import csv, re
with open('/tmp/equipaments_utf8.csv', encoding='utf-8') as f:
    header = next(csv.reader(f))   # si el separador fuera ';' -> csv.reader(f, delimiter=';')
cols = [re.sub(r'\W+', '_', h.strip()).lower() for h in header]
sql = "CREATE TABLE equipaments (\n  id INT AUTO_INCREMENT PRIMARY KEY,\n"
sql += ",\n".join(f"  `{c}` TEXT" for c in cols)
sql += "\n) CHARACTER SET utf8mb4;"
open('/tmp/create_table.sql', 'w').write(sql)
print(sql)
EOF
```

### 7.2 Crear base de datos y usuarios

```bash
sudo mysql
```

```sql
CREATE DATABASE equipaments_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- Usuario de solo lectura para el servidor web (W-N06)
CREATE USER 'webuser'@'10.6.1.10' IDENTIFIED BY '<PASSWORD_WEBUSER>';
GRANT SELECT ON equipaments_db.* TO 'webuser'@'10.6.1.10';

-- Usuario bchecker (lo exige el enunciado)
CREATE USER 'bchecker'@'%' IDENTIFIED BY '<PASSWORD_BCHECKER>';
GRANT ALL ON equipaments_db.* TO 'bchecker'@'%';

FLUSH PRIVILEGES;
```

| Usuario | Origen | Permisos | Motivo |
|---|---|---|---|
| `webuser` | `10.6.1.10` | `SELECT` | La web solo lee; si se compromete, no puede modificar datos |
| `bchecker` | `%` | `ALL` sobre `equipaments_db` | Requerido por el enunciado |

### 7.3 Crear la tabla

```bash
sudo mysql equipaments_db < /tmp/create_table.sql
```

## 8. Carga del CSV

MySQL solo lee ficheros de la carpeta indicada en `secure_file_priv` (`/var/lib/mysql-files/`):

```bash
sudo cp /tmp/equipaments_utf8.csv /var/lib/mysql-files/equipaments.csv
sudo chown mysql:mysql /var/lib/mysql-files/equipaments.csv
```

El `CREATE TABLE` incluye la columna `id` automática, que **no existe en el CSV**, así que el primer `LOAD DATA` falla por no coincidir el número de columnas. La solución aplicada fue quitar `id`, cargar y volver a añadirla:

```sql
USE equipaments_db;

ALTER TABLE equipaments DROP COLUMN id;

LOAD DATA INFILE '/var/lib/mysql-files/equipaments.csv'
INTO TABLE equipaments
CHARACTER SET utf8mb4
FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES;

ALTER TABLE equipaments ADD COLUMN id INT AUTO_INCREMENT PRIMARY KEY FIRST;
```

```text
Query OK, 2709 rows affected
Records: 2709  Deleted: 0  Skipped: 0  Warnings: 0
```

## 9. Firewall (UFW)

Solo la web debe llegar al puerto 3306:

```bash
sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow from 10.6.1.10 to any port 3306 proto tcp
sudo ufw show added
sudo ufw enable
sudo ufw status
```

```text
Status: active

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW       Anywhere
3306/tcp                   ALLOW       10.6.1.10
22/tcp (v6)                ALLOW       Anywhere (v6)
```

### Reglas en el router (R-N06)

El tráfico DMZ → Intranet pasa por el router, así que allí debe haber reglas `FORWARD` que permitan a W-N06 llegar al puerto 3306 de B-N06 y las respuestas:

```bash
iptables -A FORWARD -s 10.6.1.10 -d 10.6.2.10 -p tcp --dport 3306 -j ACCEPT
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT
```

> Estas reglas tienen efecto en el router, no en B-N06. Se documentan aquí porque son necesarias para que la conexión funcione.

## 11. Problemas encontrados

| Síntoma | Causa | Solución |
|---|---|---|
| `usermod: Permission denied` | Faltaba `sudo` | Repetir el comando con `sudo` |
| El CSV no se carga bien | Estaba en UTF-16 LE | Convertirlo con `iconv -f UTF-16 -t UTF-8` |
| `LOAD DATA` falla por número de columnas | La tabla tiene `id`, el CSV no | `DROP COLUMN id`, cargar y volver a añadir `id` |
| `ERROR 1290 --secure-file-priv` | El CSV no está en `/var/lib/mysql-files/` | Copiarlo allí con propietario `mysql` |
| `ERROR 1045 Access denied` desde W-N06 | Usuario creado con otra IP de origen o `bind-address` en `127.0.0.1` | Comprobar `mysql.user` y `ss -tlnp` |
| W-N06 no llega al 3306 | Falta regla `FORWARD` en el router o regla UFW | Revisar ambas |

## 12. Resumen de medidas de seguridad

- MySQL escucha solo en la IP de la Intranet (no en `0.0.0.0`).
- Puerto 3306 limitado por UFW a la IP de W-N06.
- Usuario de la web con solo `SELECT` y limitado a su IP de origen.
- Política de entrada `deny` en UFW; solo SSH y MySQL abiertos.
- La contraseña de los usuarios no se publica en el repositorio.
