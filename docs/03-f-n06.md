# F-N06 · Servidor de ficheros (FTP con vsftpd)

Documentación de la configuración del servidor de ficheros de la DMZ. Ofrece FTP con cada usuario enjaulado (chroot) en su propia carpeta.

## 1. Resumen

| Dato | Valor |
|---|---|
| Hostname | `F-N06` |
| Sistema operativo | Ubuntu Server 24.04 LTS |
| Red | DMZ `10.6.1.0/24` |
| IP | `10.6.1.20/24` (interfaz `enp2s0`) |
| Servicios | vsftpd 3.0.5 (FTP con chroot), SSH |
| Puertos abiertos | 21/tcp (FTP), 40000-40100/tcp (FTP pasivo), 22/tcp (SSH) |
| Usuarios FTP | `usuario1`, `usuario2` (enjaulados) y `bchecker` (en la lista de chroot) |
| Raíz FTP | `/srv/ftp/<usuario>` |

La interfaz `enp1s0` va por DHCP y es la red de gestión de Isard (Internet y acceso por SSH). La interfaz `enp2s0` es la de la DMZ.

> El nombre de la interfaz puede variar según la VM. Comprobarlo con `ip -br a` antes de editar el netplan.

```bash
ls /etc/netplan/

```

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: true
    enp2s0:
      dhcp4: false
      addresses:
        - 10.6.1.20/24
```

```bash
sudo chmod 600 /etc/netplan/*.yaml
sudo netplan try

```

Resultado esperado: `enp2s0` con `inet 10.6.1.20/24`.

## 6. Usuarios y estructura de directorios

Cada usuario queda enjaulado en `/srv/ftp/<usuario>`. vsftpd se niega a arrancar la sesión si la raíz de la jaula es escribible por el usuario, así que:

- La raíz de la jaula (`/srv/ftp/<usuario>`) pertenece a `root` y no es escribible.
- Dentro hay una subcarpeta `files/` donde el usuario sí puede escribir.

```text
/srv/ftp/
├── usuario1/          (root:root, 755)
│   └── files/         (usuario1:usuario1)
├── usuario2/          (root:root, 755)
│   └── files/         (usuario2:usuario2)
└── bchecker/          (root:root, 755)
    └── files/         (bchecker:bchecker)
```

### 6.1 `usuario1`

```bash
sudo mkdir -p /srv/ftp
sudo adduser --home /srv/ftp/usuario1 --shell /usr/sbin/nologin --no-create-home usuario1

sudo mkdir -p /srv/ftp/usuario1/files
sudo chown root:root /srv/ftp/usuario1
sudo chmod 755 /srv/ftp/usuario1
sudo chown usuario1:usuario1 /srv/ftp/usuario1/files
```

### 6.2 `usuario2`

```bash
sudo adduser --home /srv/ftp/usuario2 --shell /usr/sbin/nologin --no-create-home usuario2

sudo mkdir -p /srv/ftp/usuario2/files
sudo chown root:root /srv/ftp/usuario2
sudo chmod 755 /srv/ftp/usuario2
sudo chown usuario2:usuario2 /srv/ftp/usuario2/files
```

### 6.3 `bchecker`

El usuario ya existe (con shell normal, para SSH). Solo se crea su carpeta FTP:

```bash
sudo mkdir -p /srv/ftp/bchecker/files
sudo chown root:root /srv/ftp/bchecker
sudo chmod 755 /srv/ftp/bchecker
sudo chown bchecker:bchecker /srv/ftp/bchecker/files
```

### 6.4 Permitir el shell `nologin`

Los usuarios FTP no tienen shell de login (`/usr/sbin/nologin`). vsftpd rechaza el login si el shell no figura en `/etc/shells`, así que se añade:

```bash
echo "/usr/sbin/nologin" | sudo tee -a /etc/shells
```

## 7. Configuración de vsftpd

```bash
sudo nano /etc/vsftpd.conf
```

Valores configurados:

```ini
listen=YES
listen_ipv6=NO

anonymous_enable=NO
local_enable=YES
write_enable=YES
local_umask=022
dirmessage_enable=YES
use_localtime=YES
xferlog_enable=YES
connect_from_port_20=YES

# Chroot: cada usuario encerrado en su carpeta
chroot_local_user=YES
allow_writeable_chroot=NO
user_sub_token=$USER
local_root=/srv/ftp/$USER

# Excepciones al chroot (ver punto 8)
chroot_list_enable=YES
chroot_list_file=/etc/vsftpd.chroot_list

# Modo pasivo
pasv_enable=YES
pasv_min_port=40000
pasv_max_port=40100
pasv_address=10.6.1.20

secure_chroot_dir=/var/run/vsftpd/empty
pam_service_name=vsftpd
```

| Directiva | Función |
|---|---|
| `anonymous_enable=NO` | Desactiva el acceso anónimo |
| `local_enable=YES` / `write_enable=YES` | Permite login de usuarios locales y subir/borrar ficheros |
| `chroot_local_user=YES` | Encierra a todos los usuarios en su carpeta |
| `allow_writeable_chroot=NO` | Obliga a que la raíz de la jaula no sea escribible (por eso existe `files/`) |
| `user_sub_token` + `local_root` | Cada usuario entra en `/srv/ftp/<su_usuario>` sin depender de su home |
| `pasv_*` | Modo pasivo con rango acotado (40000-40100) para poder abrirlo en el firewall |
| `pasv_address` | IP que el servidor anuncia al cliente en modo pasivo |

Aplicar y comprobar:

```bash
sudo systemctl restart vsftpd
sudo systemctl status vsftpd
```

Debe aparecer `Active: active (running)`.

---

## 8. Usuario sin chroot (`bchecker`)

Con `chroot_local_user=YES`, la lista de `chroot_list_file` pasa a ser la lista de **excepciones**: los usuarios que aparezcan en ella no quedan enjaulados.

```bash
echo bchecker | sudo tee /etc/vsftpd.chroot_list
sudo systemctl restart vsftpd
```

> Como `local_root` sigue definido, `bchecker` entra en `/srv/ftp/bchecker` pero puede salir de esa carpeta.

## 9. Firewall (UFW)

```bash
sudo ufw allow 22/tcp
sudo ufw allow 21/tcp
sudo ufw allow 40000:40100/tcp
sudo ufw enable
sudo ufw status verbose
```

```text
Status: active
Default: deny (incoming), allow (outgoing), disabled (routed)

To                         Action      From
22/tcp                     ALLOW IN    Anywhere
21/tcp                     ALLOW IN    Anywhere
40000:40100/tcp            ALLOW IN    Anywhere
```

El rango pasivo debe abrirse porque, sin él, la conexión de control funciona pero `ls`, `get` y `put` se quedan colgados.

### Reglas en el router (R-N06)

El router debe permitir el tráfico hacia F-N06:

```bash
iptables -A FORWARD -d 10.6.1.20 -p tcp --dport 21 -j ACCEPT
iptables -A FORWARD -d 10.6.1.20 -p tcp --dport 40000:40100 -j ACCEPT
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT
```

> Estas reglas tienen efecto en el router, no en F-N06.

## 10. Pruebas

Instalar el cliente FTP en la máquina desde la que se prueba:

```bash
sudo apt update && sudo apt install -y ftp
```

### 10.1 Login, subida y descarga

```bash
ftp 10.6.1.20
```

```text
Name: usuario1
331 Please specify the password.
Password:
230 Login successful.

ftp> cd files
250 Directory successfully changed.
ftp> put /etc/hostname hostname.txt
226 Transfer complete.
ftp> ls
-rw-r--r--    1 1002     1002            6 Nov 09 14:32 hostname.txt
226 Directory send OK.
ftp> get hostname.txt /tmp/prueba.txt
226 Transfer complete.
```

Funcionan `put`, `ls` y `get`, y los datos viajan por puertos del rango pasivo (40000-40100).

### 10.2 Comprobar el chroot

```text
ftp> pwd
Remote directory: /files
ftp> cd ..
550 Failed to change directory.
```

El usuario ve su carpeta como la raíz (`/`) y no puede subir de nivel: está enjaulado.

## 11. Problemas habituales

| Síntoma | Causa | Solución |
|---|---|---|
| `500 OOPS: vsftpd: refusing to run with writable root inside chroot` | La raíz de la jaula es escribible por el usuario | `chown root:root` y `chmod 755` en `/srv/ftp/<usuario>`; el usuario escribe en `files/` |
| `530 Login incorrect` con un usuario válido | `/usr/sbin/nologin` no está en `/etc/shells` | Añadirlo con `tee -a /etc/shells` |
| Login correcto pero `ls` o `put` se cuelgan | Puertos pasivos bloqueados en UFW o en el router | Abrir `40000:40100/tcp` en ambos |
| `usermod: Permission denied` | Faltaba `sudo` | Repetir el comando con `sudo` |
| `adduser` avisa de que el home no existe | Se usa `--no-create-home` a propósito | Es normal; la carpeta se crea después con `mkdir` |

## 12. Resumen de medidas de seguridad

- Acceso anónimo desactivado.
- Cada usuario enjaulado en su carpeta (`chroot_local_user=YES`) y sin posibilidad de ver el resto del sistema.
- Raíz de la jaula propiedad de `root` y no escribible (`allow_writeable_chroot=NO`).
- Usuarios FTP sin shell de login (`/usr/sbin/nologin`).
- Rango de puertos pasivos acotado y abierto solo en ese intervalo.
- UFW con política de entrada `deny` y solo 21, 22 y 40000-40100 abiertos.
- FTP transmite en texto plano; como mejora opcional se puede activar FTPS (`ssl_enable=YES` con certificado en `/etc/ssl/private/`).
