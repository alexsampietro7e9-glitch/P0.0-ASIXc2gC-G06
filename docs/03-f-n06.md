### 2.3 Dirección IP estática (netplan)

Se edita el fichero de netplan para asignar la IP de la DMZ a la interfaz `enp2s0`:

```bash
sudo nano /etc/netplan/50-cloud-init.yaml
```

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: true
    enp2s0:
      dhcp4: false
      addresses:
        - 10.6.1.20/24
```

| Línea | Significado |
|---|---|
| `enp1s0` → `dhcp4: true` | La interfaz de gestión sigue obteniendo IP por DHCP. |
| `enp2s0` → `dhcp4: false` | Se desactiva DHCP en la interfaz de la DMZ. |
| `addresses: 10.6.1.20/24` | IP fija de F-N06 según el esquema de red. |

> **Nota:** si la máquina necesita salir a Internet por el router de la DMZ, hay que añadir la ruta por defecto en `enp2s0` (`routes: - to: default / via: 10.6.1.1`) y el DNS (`nameservers`).

La configuración se aplicó de forma segura con `netplan try`, que **revierte los cambios automáticamente a los 120 segundos** si no se confirman (evita quedarse sin acceso por un error de configuración):

```text
Press ENTER before the timeout to accept the new configuration

Changes will revert in 120 seconds
Configuration accepted.
```

## 4. Usuarios FTP y estructura de directorios

### 4.1 Idea general

Cada usuario se encierra (*chroot*) en `/srv/ftp/<usuario>`. vsftpd **se niega a funcionar** si la raíz de la jaula es escribible por el usuario, por lo que la estructura es:

```text
/srv/ftp/usuario1/          ← raíz de la jaula: propietario root, permisos 755 (solo lectura para el usuario)
└── files/                  ← subcarpeta donde sí puede escribir: propietario usuario1
```

### 4.2 Creación de `usuario1`

```bash
sudo mkdir -p /srv/ftp
sudo adduser --home /srv/ftp/usuario1 --shell /usr/sbin/nologin --no-create-home usuario1
sudo mkdir -p /srv/ftp/usuario1/files
sudo chown root:root /srv/ftp/usuario1
sudo chmod 755 /srv/ftp/usuario1
sudo chown usuario1:usuario1 /srv/ftp/usuario1/files
```

```text
isard@F-N06:~$ sudo mkdir -p /srv/ftp
isard@F-N06:~$ sudo adduser --home /srv/ftp/usuario1 --shell /usr/sbin/nologin --no-create-home usuario1
info: The home dir /srv/ftp/usuario1 you specified can't be accessed: No such file or directory

info: Adding user `usuario1' ...
info: Selecting UID/GID from range 1000 to 59999 ...
info: Adding new group `usuario1' (1002) ...
info: Adding new user `usuario1' (1002) with group `usuario1 (1002)' ...
info: Not creating home directory `/srv/ftp/usuario1'.
New password:
Retype new password:
passwd: password updated successfully
info: Adding new user `usuario1' to supplemental / extra groups `users' ...
info: Adding user `usuario1' to group `users' ...
```

> El aviso `can't be accessed: No such file or directory` es normal: la carpeta aún no existe y se crea a mano justo después.

```text
isard@F-N06:~$ sudo mkdir -p /srv/ftp/usuario1/files
isard@F-N06:~$ sudo chown root:root /srv/ftp/usuario1
isard@F-N06:~$ sudo chmod 755 /srv/ftp/usuario1
isard@F-N06:~$ sudo chown usuario1:usuario1 /srv/ftp/usuario1/files
```

| Comando / opción | Qué hace y por qué |
|---|---|
| `mkdir -p /srv/ftp` | Crea la carpeta base de todos los usuarios FTP (`-p` crea también padres si faltan). |
| `--home /srv/ftp/usuario1` | Define el *home* del usuario dentro de `/srv/ftp`, separado de `/home`. |
| `--shell /usr/sbin/nologin` | El usuario **no puede iniciar sesión por SSH ni en consola**: solo sirve para FTP. Es una medida de seguridad. |
| `--no-create-home` | No crea el home automáticamente, porque lo creamos a mano con los permisos correctos. |
| `chown root:root` + `chmod 755` en la raíz de la jaula | Requisito de vsftpd: la raíz del chroot no debe ser escribible por el usuario. |
| `chown usuario1:usuario1 .../files` | La subcarpeta `files` sí pertenece al usuario, que puede subir y borrar ahí. |

### 4.3 Permitir `nologin` en `/etc/shells`

```bash
echo "/usr/sbin/nologin" | sudo tee -a /etc/shells
```

```text
isard@F-N06:~$ echo "/usr/sbin/nologin" | sudo tee -a /etc/shells
/usr/sbin/nologin
```

**Por qué:** vsftpd (a través de PAM) solo acepta usuarios cuyo shell figure en `/etc/shells`. Sin esta línea, los usuarios con `nologin` recibirían `530 Login incorrect`. `tee -a` añade la línea **al final** del fichero con permisos de administrador (con `>>` y `sudo` no funcionaría, porque la redirección la hace el shell sin privilegios).

### 4.4 Creación de `usuario2`

Mismo procedimiento que con `usuario1`:

```bash
sudo adduser --home /srv/ftp/usuario2 --shell /usr/sbin/nologin --no-create-home usuario2
sudo mkdir -p /srv/ftp/usuario2/files
sudo chown root:root /srv/ftp/usuario2
sudo chmod 755 /srv/ftp/usuario2
sudo chown usuario2:usuario2 /srv/ftp/usuario2/files
```

```text
info: Adding new group `usuario2' (1003) ...
info: Adding new user `usuario2' (1003) with group `usuario2 (1003)' ...
info: Not creating home directory `/srv/ftp/usuario2'.
passwd: password updated successfully
```

### 4.5 Carpeta FTP para `bchecker`

```bash
sudo mkdir -p /srv/ftp/bchecker/files
sudo chown root:root /srv/ftp/bchecker && sudo chmod 755 /srv/ftp/bchecker
sudo chown bchecker:bchecker /srv/ftp/bchecker/files
```

**Por qué:** `bchecker` ya existe con shell normal (se usa por SSH), así que solo hace falta crear su carpeta FTP con los mismos permisos que el resto.

## 5. Configuración de vsftpd

Se edita el fichero principal:

```bash
sudo nano /etc/vsftpd.conf
```

Directivas finales (fragmentos relevantes del fichero):

```ini
listen=YES
listen_ipv6=NO

anonymous_enable=NO
local_enable=YES
write_enable=YES
local_umask=022
dirmessage_enable=YES
use_localtime=YES

# Chroot: cada usuario encerrado en su carpeta
chroot_local_user=YES
allow_writeable_chroot=NO
user_sub_token=$USER
local_root=/srv/ftp/$USER

# Modo pasivo
pasv_enable=YES
pasv_min_port=40000
pasv_max_port=40100
pasv_address=10.6.1.20

secure_chroot_dir=/var/run/vsftpd/empty
pam_service_name=vsftpd
```

### Justificación de cada directiva

| Directiva | Valor | Por qué |
|---|---|---|
| `listen` | `YES` | vsftpd funciona como servicio independiente (no lanzado por `inetd`). |
| `listen_ipv6` | `NO` | Solo se escucha en IPv4; vsftpd no puede escuchar en IPv4 e IPv6 a la vez con una sola instancia. |
| `anonymous_enable` | `NO` | Se **prohíbe el acceso anónimo**: solo entran usuarios con cuenta. |
| `local_enable` | `YES` | Permite iniciar sesión a los usuarios locales del sistema (`usuario1`, `usuario2`, `bchecker`). |
| `write_enable` | `YES` | Permite comandos de escritura (subir, borrar, crear carpetas). |
| `local_umask` | `022` | Los ficheros subidos quedan con permisos `644` (el resto puede leer, solo el dueño escribe). |
| `dirmessage_enable` | `YES` | Muestra mensajes al entrar en un directorio, si existen. |
| `use_localtime` | `YES` | Los listados muestran la hora local y no GMT. |
| `chroot_local_user` | `YES` | **Encierra a todos los usuarios locales** en su directorio raíz: no pueden ver el resto del servidor. |
| `allow_writeable_chroot` | `NO` | Mantiene la política segura: la raíz de la jaula **no** puede ser escribible (por eso existe la subcarpeta `files`). |
| `user_sub_token` | `$USER` | Define la variable que se sustituye por el nombre del usuario en `local_root`. |
| `local_root` | `/srv/ftp/$USER` | Cada usuario entra directamente en `/srv/ftp/<su_nombre>`, sin depender de su *home* real. |
| `pasv_enable` | `YES` | Activa el **modo pasivo**, necesario cuando hay firewall o router entre cliente y servidor. |
| `pasv_min_port` / `pasv_max_port` | `40000` / `40100` | Rango acotado de puertos para las conexiones de datos, para poder abrirlo en el firewall. |
| `pasv_address` | `10.6.1.20` | IP que el servidor anuncia al cliente para conectar a los datos. |
| `secure_chroot_dir` | `/var/run/vsftpd/empty` | Directorio vacío y no escribible que vsftpd usa internamente como jaula segura. |
| `pam_service_name` | `vsftpd` | Servicio PAM que valida usuario y contraseña. |

## 6. Excepción de chroot para `bchecker`

Con `chroot_local_user=YES`, la lista indicada en `chroot_list_file` funciona **al revés**: los usuarios que aparecen en ella quedan **excluidos** del chroot. Se usa para que `bchecker` (el corrector) no esté enjaulado.

En `/etc/vsftpd.conf`:

```ini
chroot_list_enable=YES
chroot_list_file=/etc/vsftpd.chroot_list
```

Se crea la lista y se reinicia el servicio:

```bash
echo bchecker | sudo tee /etc/vsftpd.chroot_list
sudo systemctl restart vsftpd
```

```text
isard@F-N06:~$ echo bchecker | sudo tee /etc/vsftpd.chroot_list
bchecker
isard@F-N06:~$ sudo systemctl restart vsftpd
```

> **Importante:** `local_root=/srv/ftp/$USER` se sigue aplicando a `bchecker`, así que entra en `/srv/ftp/bchecker`, pero ya no está enjaulado.

## 9. Errores encontrados y cómo se resolvieron

| Error | Causa | Solución |
|---|---|---|
| `553 Could not create file` al hacer `put /etc/hostname` | Sin nombre remoto, `put` intenta crear el fichero en `/etc/hostname` dentro de la jaula (ruta inexistente), y además se estaba en la raíz de la jaula, que no es escribible. | Entrar en `files` y dar nombre remoto: `cd files` + `put /etc/hostname hostname.txt`. |
| `Not connected` al ejecutar `cd files` en `ftp>` | Se abrió el cliente con `ftp` **sin dirección**, así que no había sesión. | Conectar con `ftp 10.6.1.20`. |
| `530 Login incorrect` | Contraseña mal tecleada (no se ve al escribirla). Otras causas posibles: falta `/usr/sbin/nologin` en `/etc/shells` o cuenta bloqueada. | Reintentar la contraseña; si persiste, revisar `/etc/shells` y `sudo passwd -S usuario1`, o restablecerla con `sudo passwd usuario1`. |
| `500 OOPS: vsftpd: refusing to run with writable root inside chroot` *(error típico, evitado en este montaje)* | La raíz de la jaula es escribible por el usuario. | `chown root:root` + `chmod 755` en la raíz y subcarpeta `files` para escribir. |
| `ls` se cuelga tras conectar *(error típico, evitado en este montaje)* | Puertos pasivos bloqueados en UFW o en el router. | Abrir `40000:40100/tcp` en UFW y en el router. |

### Observación: vsftpd instalado por error en B-N06

Durante el proceso se ejecutó la instalación de vsftpd también en la máquina **B-N06** (servidor MySQL), donde no corresponde. Se recomienda eliminarlo para dejar esa máquina solo con los servicios que le tocan:

```bash
sudo apt purge -y vsftpd
sudo apt autoremove -y
```
